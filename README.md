# Offline AudioSet (YAMNet) Classification + Visualization

This directory runs **offline audio event classification** using **YAMNet (AudioSet / 521 classes)** and produces a **time-stamped label timeline** at a configurable sampling rate. It also includes lightweight **Streamlit** apps to visualize results or compare real-time and offline classification.

---

## What’s in this folder

- `offlineclassify.py` — CLI tool: audio file → `predictions.jsonl`
- `viz_app.py` — Streamlit dashboard to explore results
- `dashboard_compare.py` — Streamlit dashboard to run offline inference on uploaded audio and/or compare against uploaded annotations (real-time vs offline)
- `yamnet.tflite` — YAMNet TensorFlow Lite model
- `yamnet_class_map.csv` — Label map (521 AudioSet classes for YAMNet)
- `predictions.jsonl` — Output file (generated by `offlineclassify.py`)
- `Recording.wav` — Example audio file
- `requirements.txt` — Python dependencies (optional but recommended)
- `label_extractor.py` — (Optional) helper for extracting labels from TFLite metadata (not required if using `yamnet_class_map.csv`)
- `metadata.json` — Project metadata (not required for inference)

## Setup

### 1) Create an environment (recommended)
Using conda:
```bash
conda create -n yamnet_offline python=3.11 -y
conda activate yamnet_offline
pip install -r requirements.txt
```

*MacOS Note: if `soundfile` fails to install, install `libsndfile` first:*
```bash
brew install libsndfile
pip install soundfile
```

*MacOS Note: system may also require `ffmpeg` to process m4a, mp3, and mp4 audio files:*
```bash
brew install ffmpeg
```

*MacOS Note: tensorflow may require specialized macOS packages.* <br>
*If tensorflow fails to install remove the tensorflow line from requirements.txt and install the Apple packages instead.*
```bash
tensorflow-macos (and optionally tensorflow-metal)
```

### 2) Running Offline Classification
Run the classifier and write results to predictions.jsonl:

```bash
python offlineclassify.py --audio Recording.wav --sample_hz 1.0 --top_k 5
```

<h4>CLI arguments</h4>

* `--audio` (required): Path to an audio file (.wav, .flac, etc.).
* `--sample_hz` (default: 1.0): How often to emit predictions (frames per second).
  * Example: 2.0 → prediction every 0.5s, 0.5 → prediction every 2s.
* `--top_k` (default: 5): Number of top labels to save per frame.
* `--window_s` (default: 0.975): Window size (seconds) used for each prediction.
* `--avg_frames` (default: 1): Temporal smoothing (averages last N frames).
* `--out_json` (default: predictions.jsonl): Output path for results.
* `--model` (default: yamnet.tflite): Model path.
* `--labels` (default: yamnet_class_map.csv): Label map path.


<h4>Ex. with smoothing and custom output:</h4>

```bash
python offlineclassify.py \
  --audio Recording.wav \
  --sample_hz 2.0 \
  --avg_frames 5 \
  --top_k 3 \
  --out_json my_preds.jsonl
```

<h4>Output Format</h4>
The output is JSON Lines (one JSON object per time step). The default output filename is [predictions.jsonl].

Each line looks like:
```json
{
  "t_sec": 12.487,
  "top": [
    {"label": "Speech", "score": 0.83},
    {"label": "Music", "score": 0.12},
    {"label": "Vehicle", "score": 0.04}
  ]
}
```
- t_sec is the center time of the analysis window.
- top is the ranked list of top-k labels and their probabilities.

### 3) Visualizing Results (Streamlit Dashboard)
A localhost dashboard is provided via Streamlit. Input the path to the output file with JSON predictions on the Streamlit dashboard page.

What it includes:
- Scatter timeline of top-1 label over time
- Confidence threshold slider
- Collapsed “event segments” table (contiguous runs)
- Ability to inspect full top-k at a selected timestamp

To run the dashboard:

```bash
streamlit run viz_app.py
```

<br><br>

### 4) Upload + Compare Dashboard (dashboard_compare.py)

This dashboard supports three workflows:
- Upload an audio file → run offline classification → step through predictions.
- Upload an annotations file (real-time Android output or offline output) → step through predictions.
- Upload audio + real-time annotations → run offline classification on the audio and compare real-time vs offline side-by-side.

<h4>Running the comparison dashboard:</h4>

```bash
streamlit run dashboard_compare.py
```

<h4>What you can do in the compare view</h4>

- Select a time with a slider and see the nearest frame from both systems
- View top-k label tables for real-time and offline at that time
- Compare top-1 timelines visually
- Apply confidence filtering to reduce noise

<h4>Supported audio formats</h4>
Recommended: wav <br>
Also supported (if your install includes the mp3/m4a loader): mp3, mp4, m4a, flac, ogg, aiff, aif, aifc. 

*Note: mp3/m4a support typically requires ffmpeg.* <br>
*On macOS:*
```bash
brew install ffmpeg
```

<h4>Supported annotation formats</h4>
The dashboard accepts:

- `JSONL` in the same format as offlineclassify.py output (recommended)
- `JSON` with a list of predictions (or { "predictions": [...] })
- `CSV` (see the compatibility format below)


<h4>Recommended annotation schema (JSONL)</h4>
One JSON object per line:

```json
{"t_sec":0.975,"top":[{"label":"Speech","score":0.83},{"label":"Music","score":0.12}]}
{"t_sec":1.975,"top":[{"label":"Speech","score":0.79},{"label":"Music","score":0.15}]}
```
*Note: The system is designed to be compatible with the CSV annotation format outputted by the real-time Android app. The system uses a converter to parse the CSV annotations into the above format for comparison.*

<br><br>

<h1>Additional Notes</h1>

- The pipeline converts audio to mono and resamples to 16 kHz (required by YAMNet).
- metadata.json is not used by the classifier; it is optional project documentation.
- Offline classification only exports the top k labels by score in every frame (does not export the full 521-dim label vector)
